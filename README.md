# Activity Forge

**[Открыть конструктор →](https://manabreaker.github.io/activity-forge/)**

Настройте декоративный календарь GitHub, сравните варианты и опубликуйте выбранный план в отдельный приватный репозиторий. История явно обозначена как декоративная и не изображает работу над программным продуктом.

## Как пользоваться

1. Откройте сайт. Вход для превью не нужен.
2. Выберите характер: короткие всплески, мягкие волны или островки активности.
3. Настройте период, интенсивность, выходные и перерывы. «Ещё один вариант» меняет seed.
4. Посмотрите «Результат», «Сейчас» и «Добавится». Выберите день, чтобы увидеть точные timestamps. Экспортируйте PNG, SVG, HTML, JSON или CSV.
5. Нажмите «Выбрать этот рисунок» и подключите GitHub. Если приложение ещё не установлено, сайт предложит настроить доступ.
6. Загрузите текущую активность или явно отключите её учёт. После загрузки выберите обновлённый рисунок ещё раз.
7. Укажите новое имя приватного репозитория. Проверьте имя, период, число коммитов и ID плана, поставьте галочку и подтвердите публикацию.
8. В профиле GitHub включите **Contribution settings → Private contributions**. Обновление календаря может занять время.
9. При желании отзовите доступ кнопкой внизу. Удаление установки приложения выполняется отдельно в настройках GitHub.

При прерывании публикации сохраняйте исходный план и имя репозитория: повторная проверка отправляет ту же историю и проверяет точный HEAD. Не очищайте браузер до выяснения результата. Приложение не удаляет созданные репозитории.

## Где что работает

```text
GitHub Pages                     Stateless API Worker             GitHub
┌─────────────────────┐          ┌────────────────────────┐        ┌──────────────┐
│ UI + исходный Go    │ OAuth    │ PKCE/state + обмен кода│        │ GitHub App   │
│ генератор в WASM    │─────────→│ токен только в RAM     │───────→│ calendar API │
│                     │ запрос  │ проверки плана/доступа │        │ новый private│
│ localStorage: планы │─────────→│ Git pack только в RAM │───────→│ repository   │
│ sessionStorage:     │          │ без БД и файлов       │        └──────────────┘
│ encrypted auth ≤1ч │          └────────────────────────┘
└─────────────────────┘
```

GitHub Pages не исполняет серверный код. OAuth client secret хранится только в runtime secrets API. Интерфейс и все исходники находятся в этом репозитории; backend развёртывается отдельно. Ни Git, ни Go, ни GitHub CLI посетителю сайта не нужны.

Генератор один: `cli/internal/forge`, тот же алгоритм используется браузером через `cli/cmd/browser`. JavaScript не генерирует альтернативный рисунок. При публикации сервер проверяет SHA-256 канонического плана, автора, timestamps и статистику, собирает Git pack в памяти, создаёт пустую ветку с ожидаемым старым SHA `000…000` и сверяет итоговый HEAD. Force push не используется.

## Разрешения

| GitHub App permission | Для чего |
|---|---|
| Repository creation: write | Создать подтверждённый пользователем репозиторий |
| Contents: read/write | Отправить историю и проверить результат |
| Metadata: read | Проверить владельца, приватность и основную ветку |

Права GitHub действуют на репозитории, выбранные пользователем при установке приложения. **Не обещаем**, что GitHub технически ограничит разрешение только будущим новым репозиторием: это зависит от установки. Сервис дополнительно запрещает публикацию в репозиторий без своего маркера, другого владельца или с посторонней историей. App не запрашивает administration, удаление репозиториев, почту, issues, pull requests или workflows.

Автор — GitHub login и соответствующий `ID+login@users.noreply.github.com`; неподтверждённый email из формы не принимается.

## Данные

Настройки, snapshot текущей активности, зафиксированный план и квитанция публикации сохраняются в браузере. Авторизация в sessionStorage зашифрована AES-GCM и действует до часа; обычный токен провайдера браузеру не передаётся. Для OAuth используется временная HttpOnly cookie, `state`, S256 PKCE и nonce вкладки; third-party cookies не нужны. Ключ API хранится как секрет сервиса. Refresh token не сохраняется и не используется.

Backend не пишет пользовательские данные в БД, файлы или логи приложения. Git-объекты существуют только в памяти запроса. У приложения нет аналитики, внешних шрифтов, CDN-скриптов или клиентских ошибок, отправляемых в сторонний сервис. Очистка браузера не отзывает авторизацию на GitHub. GitHub хранит репозиторий и авторизации; хостинг может обрабатывать технические метаданные. Подробности и требования к инфраструктурным логам: [docs/privacy.md](docs/privacy.md).

## Разработка

Нужны Node.js 24, Go 1.25+ и Git для интеграционных проверок. Нет npm-зависимостей; модуль Go использует стандартную библиотеку. Установка пакетов не требуется.

```sh
node --test tests/*.test.mjs
cd cli
go test -race ./...
make lint
cd ..
node scripts/build.mjs
node scripts/check-wasm.mjs
node scripts/validate-artifact.mjs
node scripts/dev.mjs
```

Откройте `http://127.0.0.1:4317`. API запускается на `4318`. Без GitHub App превью и экспорт полностью доступны, вход честно показывает, что ещё не настроен. В тестах реальные репозитории GitHub не создаются.

## Публикация и настройка OAuth

Сайт опубликован из ветки `gh-pages` (Settings → Pages → Deploy from a branch). Обновление после локальных проверок: `node scripts/build.mjs`, `node scripts/check-wasm.mjs`, `node scripts/publish-pages.mjs Manabreaker/activity-forge`. Скрипт отправляет обычный fast-forward commit со статикой; исходники остаются в `main`.

Workflow `.github/workflows/pages.yml` оставлен для ручного запуска: он проверяет Node/Go, собирает WASM, выполняет smoke и публикует `dist/pages`. Для него нужно переключить Source на GitHub Actions. В первоначальном окружении hosted runner не запустился до выполнения шагов. Вариант из ветки `gh-pages` опубликован штатным Pages build без этого runner.

API: [docs/deployment.md](docs/deployment.md). Ключи не должны попадать в код, `.env`, артефакты или Git. Для собственного fork измените `web/config.js`, `connect-src` в `web/index.html` и адреса в настройках App. Значения `FRONTEND_URL` и `API_ORIGIN` должны точно соответствовать вашим адресам.

## CLI

Полная исходная кроссплатформенная утилита находится в [`cli/`](cli/README.md): интерактивный мастер, локальное браузерное превью, генерация, inspect и подтверждаемая публикация через Git/GitHub CLI. Для сборки: `cd cli && go build -o activityforge .`; дружелюбный запуск: `go build -o activity-forge-friend ./cmd/friend`.

## Проверки и ограничения

Автотесты проверяют подмену/истечение сессии, state/nonce handoff, CORS, неизменяемый план, будущие даты, автора, импорт pack обычным Git, сохранение точного назначения при retry, защиту приватного репозитория, посторонний HEAD и идемпотентность. WASM smoke проверяет повторяемость и SHA-256 полного плана. Копия CLI проверяется `go test -race ./...` и `make lint`.

Максимум веб-плана: 366 дней и 4000 коммитов. Цвета — прогноз; алгоритм уровней GitHub и время обработки могут менять отображение. Блокировщики скриптов/storage могут мешать входу и сохранению настроек. Живой OAuth, установка App с минимальным набором репозиториев и отправка истории требуют отдельной проверки на настроенном приложении; зелёные локальные тесты сами по себе этого не доказывают.
